# 本地数据库

默认使用四个来源按钮：**Bangumi、E-Hentai、MangaBaka、BookWalker**。
在支持的桌面 Chromium/Tampermonkey 中，点击后自动下载原始数据、新建数据库、建立检索索引并加载；不需要填写 URL、SHA-256，也不需要预先创建空 SQLite 文件。Bangumi 地址从上游最新清单解析。

- 下载按实际字节显示进度；构建显示阶段和已处理条目数。任务可取消，失败不替换已有有效库。
- 每个来源独立加载，可同时保留四个来源。本地命中不请求该来源在线详情；无命中再按既有规则兜底。
- 在面板中构建的库保存在当前站点的浏览器本地存储，重新打开自动恢复；可使用「导出数据库」保存为普通 SQLite 文件。
- 「已有文件」默认折叠：可以加载已有检索数据库，或选择已下载的原始档案进行构建。原始 SQLite 和本工具的检索数据库不是同一种格式，前者要走构建入口。
- 取消文件选择只是取消选文件，不关闭插件、不清空搜索词或已加载库；插件本身的 Escape 关闭行为保留。

## 限制

1. **自动构建依赖安全上下文和 OPFS。** 通常需要有效 HTTPS；`localhost`/loopback HTTP 是浏览器例外。普通内网 HTTP 仍可下载原始数据、选择并按页查询已构建库，但不能运行当前 OPFS 构建流程。不是 SQLite 本身不能在 HTTP 使用。
2. **下载文件夹不等于文件读取授权。** `GM_download` 完成后只返回下载结果，不能把任意磁盘文件交给脚本。自动流程改用 GM 流式响应直接写浏览器本地存储，保留文件句柄继续构建；管理器不支持流式响应时显示「仅下载原始数据」替代入口，随后需自行选取文件。
3. **浏览器存储不是备份。** 清理站点数据、换浏览器或换站点地址会影响可见的数据库；建议导出。手动选取的外部 SQLite 只读、不整库复制，刷新后需要再次选择。
4. **空间和时间取决于来源规模。** 构建期间需要容纳压缩输入、解压源、暂存索引和新库；更新时还保留旧库。索引可能占用明显内存，不能保证所有大型数据库在低配设备上构建成功。构建期间不要关闭页面。资源不足可用 [原生 CLI](../catalog/INTEGRATION.md)。
5. 数据仍来自上游；网络、上游更新、权限或格式变化可能失败。当前无断点续传；正常失败/取消会清理本次临时文件，突然终止浏览器可能留下临时文件。

## 验证范围

- 四种来源格式均有真实浏览器 Worker 的合成档案构建、查询和错误路径测试；同时验证四来源并存、自动保存恢复及普通 HTTP 只读查询。
- 本轮使用真正的 Tampermonkey 和隔离 Komga，自动下载公开完整 BookWalker 档案，在浏览器构建 **14,379 条**、自动加载，刷新恢复后搜索「葬送」得到 **3 条**结果；同时加载外部 Bangumi 库后两个来源仍可用。
- 上述是 BookWalker 的全量浏览器端验收，**不等于其他三个来源的全量浏览器构建已经逐一验收**。历史原生构建与其他实际验收见 [VALIDATION.md](../VALIDATION.md)。
- 本项目不在 Release 中分发上游档案或预建目录。
